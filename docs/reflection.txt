1. Which AI tools, if any, did you use, and at which stages of the work?

I used ChatGPT mainly as a technical support tool while developing NetMessenger. I used it when I needed clarification about networking concepts, TCP behaviour, error handling, testing methods, and assignment requirements. I also asked questions while working on areas such as TCP command framing, select()-based multi-client handling, file transfer, disconnect handling, and final testing. I compiled, executed, debugged, and tested the application in my own Linux environment before accepting any changes or conclusions.


2. What did the AI do well? Where did it get things wrong or mislead you?

ChatGPT was useful for explaining networking concepts in a simple way. In particular, the explanation that TCP is a continuous byte stream helped me understand why one recv() call cannot be assumed to contain exactly one complete command. It was also useful for suggesting additional edge-case tests such as partial commands, zero-byte files, binary files, and oversized file requests.

However, AI suggestions still needed to be checked against the actual application state. For example, during one file-transfer test I received USER_NOT_FOUND because the intended recipient was not connected. The test setup had to be corrected before the expected result could be verified. Some suggestions were also more general than necessary and had to be adapted to my own implementation.


3. What did you change, add, or reject from any AI output, and why?

I did not automatically apply every suggestion. I compared suggestions with the assignment specification and with the structure of my own program. I adjusted ideas where they did not exactly match my client state, room management, file-transfer flow, or fixed protocol requirements. I also avoided unnecessary additions that were outside the assignment scope. Testing was used to confirm whether an approach actually worked before I kept it in the final project.


4. What did you learn about your own understanding of network programming through completing this assignment?

The assignment improved my understanding of TCP socket programming significantly. I learned that TCP does not preserve application message boundaries and that proper buffering is required for partial and combined commands. I also gained practical experience with select(), per-client state management, username and room tracking, graceful and unexpected disconnects, protocol parsing, and transferring raw binary data over the same connection used for text commands.

The testing stage was especially useful because it showed me the importance of validating assumptions using real network behaviour. Verifying file transfers with SHA-256 hashes and testing multiple simultaneous clients gave me more confidence in understanding how the complete client-server system works.
